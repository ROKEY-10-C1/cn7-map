# CN7 휠 조립 셀 공정 시나리오

이 문서는 팀 합의 공정, 상태 전이, 안전 조건과 구현 상태의 기준이다. 로봇 내부 STEP은 각 파트의 구현 문서에서 관리한다.

## 고정 배치와 공정 순서

타이어는 1F 공급 구역에서 경사 컨베이어를 타고 B1으로 내려와 좌우 장착 픽업점까지 이동한다. 컨베이어·지지대·가드는 AMR과 CN7 차체, 가조립·체결 휠을 포함한 통과 외형을 기준으로 배치한다. 장착·체결 RS080N은 바닥 고정식이고 명목 작업점은 World에 고정한다. AMR이 차체를 움직여 작업 대상 허브를 그 점에 맞춘다.

| 단계 | 상위 상태 | 작업과 완료 조건 |
|---|---|---|
| 1 | `VEHICLE_LOADING` → `VEHICLE_PARKING` | 차량을 적재하고 +X 방향으로 A에 전방 주차한다. 전륜과 장착점의 정렬을 확인한다. |
| 2 | `FRONT_MOUNTING` | 좌우 전륜을 가조립한다. 유지 상태 확인 후 그리퍼를 놓고 안전 위치로 후퇴한다. |
| 3 | `AMR_FIRST_MOVE` | 휠베이스 2.720 m만큼 전진해 B에 정차한다. 전륜은 체결점, 후륜은 장착점에 맞춘다. |
| 4 | `PARALLEL_OPERATION` | 전륜 체결과 후륜 가조립을 병렬로 수행하고 결과를 독립적으로 기록한다. |
| 5 | `PARALLEL_OPERATION` 완료 확인 | 두 작업 완료, 양쪽 공구 안전 후퇴, 가조립 휠과 체결 너트의 이동 중 유지 조건을 모두 확인한다. |
| 6 | `AMR_SECOND_MOVE` | 2.720 m 더 전진해 C에 정차하고 후륜을 고정 체결점에 맞춘다. |
| 7 | `NUT_RELOADING` → `REAR_FASTENING` | 정차 후 고정 재장전 박스에서 새 너트를 장전한다. 후륜 체결·안착 확인, 소켓 분리 및 후퇴를 완료한다. |
| 8 | `VEHICLE_EXIT` → `COMPLETE` | 네 휠의 체결 결과, 차량 적재 유지, 로봇 후퇴 및 출차 경로를 확인하고 전방으로 출차한다. 출차점을 지나 동쪽 복귀 통로까지 직진한 뒤 −y로 이동해 출고 칸 줄 머리에 도착하면 셀 공정이 끝난다. 뒤로 셀을 다시 지나가지 않는다. |

## 공정 상태와 인터록

- 중앙 제어의 시작 상태는 `IDLE`이다. 각 차량의 FL·FR·RL·RR 상태를 `WAITING → MOUNTING → MOUNTED → FASTENING → FASTENED`로 따로 추적한다. 실패 휠과 상위 공정은 `ERROR`로 기록하고 실패 단계, 측정값, 원인을 남긴다.
- 작업 시작은 AMR 정차, 차량 자세·허브 오차 기준 충족, 작업 구역 안전, 선행 공정 완료가 조건이다. 장착에는 타이어 픽업 준비와 파지 확인이, 체결에는 소켓별 너트 5개 장전과 스터드 진입 가능 확인이 추가된다. 타이어 검사·불량 배출은 공급 경로에서 처리하며 비전 위치와 검사 기준은 후속 확정 대상이다.
- 장착기는 파지·자세 전환 후 휠과 허브의 중심·축·패턴을 맞춰 삽입하고, 휠 유지 확인·그리퍼 해제·후퇴를 모두 완료한 뒤 장착 완료를 알린다. 같은 휠을 체결 중 계속 잡는 절차는 과거 검토 방식이다.
- AMR 이동은 로봇이 차량 통과 영역을 벗어나고, 적재·가조립 휠·체결 너트가 유지되며, 경로가 비어 있을 때 허용한다. 이동 중에는 차량에 대한 로봇 작업을 차단한다. B에서는 전륜 체결과 후륜 가조립 모두에 완료 조건을 적용한다. 오류·타임아웃 뒤에는 원인 해소와 안전 상태 확인을 거쳐 재개한다.
- 고정 재장전 박스에서는 접근·TCP 정렬·너트 5개 장전·후퇴를 확인한다. 앞서 체결한 너트는 차량에 남기고 신규 너트에는 고유 Prim 경로를 부여한다. 체결 로봇 내부 상태와 기본 시험의 재장전 순서는 [체결 README](../map_fasten/README.md#체결-로봇-내부-step)에서 관리한다.

## World 좌표와 물리 기준

- World는 +X 전진, +Y 차량 왼쪽, +Z 위이며 B1 시험 바닥은 Z=0이다. 차량·AMR·허브·휠은 이동하는 프레임이고, 로봇 베이스·명목 작업점·재장전 박스는 고정 프레임이다. TCP, 센서, 허브 및 차량 프레임을 구분하며, IK는 World 목표를 로봇 베이스 프레임으로 변환한다. 후륜 윤거·허브 높이·볼트 위상·적재 오프셋은 측정값으로 확인하고 허용 오차 밖에서 작업을 시작하지 않는다.
- 기본 단위는 m·s·N·N·m, 내부 각도는 rad, PhysX 회전 드라이브는 deg다. 속도 단위는 로그에서 명시한다.
- 통합 공정은 하나의 PhysX 스텝으로 구동한다. 초기 배치와 독립 시험의 초기화는 정상 이송과 구분하며, 물체 순간이동으로 성공 처리하지 않는다. 가조립 휠과 체결 너트는 차량·허브와의 상대 관계를 유지해야 한다. 차량을 움직이는 공정에서는 너트를 World Fixed Joint에 고정하지 않는다. 휠 기울기·축방향 이동·이탈과 너트 잔류를 검증하고, 피치 기반 이송·Joint 고정·나사산 접촉·최종 토크는 서로 다른 검증 결과로 기록한다.

## 구현과 확정 설계의 차이

| 항목 | 현재 구현 상태 (`main`) | 다음 구현·검증 |
|---|---|---|
| 공급 | 좌우 두 경사 라인이 1F에서 B1 픽업점까지 이송한다. CPU PhysX `--supply-probe`에서 좌우 각각 한 개가 픽업 준비 상태에 도달했다. 라이브 셀의 후륜(RL·RR) 픽업 구역은 아직 이전 구조대로 X −1.360 m에 따로 생성되고, 휠은 1F가 아니라 B1 벨트 위(축 X + 0.76 m)에서 생성된다. | 후륜도 같은 픽업점(X 0.270 m)에서 전륜 다음 순서로 받도록 픽업 구역을 공유하고, 연속 투입·낙하·끼임 보호를 검증한다. |
| A/B/C 정차·출고 | 리플레이는 C까지 전진해 후륜을 체결하고 전방 출차한 뒤 동쪽 복귀 통로로 출고 칸 줄 머리까지 간다. 출고 칸에 내려놓는 장면은 없다. `Cell.advance_amr()`은 시험용 신호로 출차점까지의 적재 주행을 확인했고, 라이브 셀은 출차점 이후를 구동하지 않는다. 도크 클램프는 A에만 있어 B·C에서는 AMR 서보만 위치를 유지한다. | 실제 완료·안전·적재 유지 신호와 연결하고, B·C 고정 수단과 복귀 통로·출고 칸 진입을 라이브 물리로 검증한다. |
| 고정 로봇과 병렬 공정 | 고정 베이스를 쓴다. 리플레이는 [cell_motion.py](../wheel_cell/cell_motion.py)의 계획을 재생한다. [라이브 셀](../wheel_cell/cell.py)에는 장착 모델과 물리가 있지만, 전체 장착·체결을 A/B/C 상태에 맞춰 실행하는 제어는 미연동이다. | 실측 정렬을 시작 조건에 연결하고 B의 장착·체결 병렬 동작과 안전 후퇴를 검증한다. |
| 휠과 너트의 이송 | 리플레이의 타이어·너트는 차량 계층을 따라간다. 통과 시험은 가조립 휠을 포함한 외형과 적재 차체 주행을 검사했다. [인계 시험](../wheel_cell/HANDOVER.md)은 정지 상태다. 체결 단독 시험의 기본 모드는 World 고정이고 물리 나사 옵션은 실험 단계다. | 가조립 휠의 두 번 인덱싱 중 유지, 허브 상대 너트 결합과 이송 후 잔류, 실제 물림·토크를 검증한다. |

## 차량 버퍼 설계·실험 기록 (2026-11-26~27)
차량 버퍼는 입고(+y, 바퀴 없는 차)·출고(-y, 완성차) 각 3칸이 x -3.12 / 0 / 3.12에 한 줄로 붙어 있고, 차는 칸에 90°로 놓인다. 입고 칸은 서쪽 통로 x = -7.5에서, 출고 칸은 동쪽 복귀 통로 x = 13.1에서 드나든다. 칸 사이에 따로 통로를 만들지 않고 **칸 순서를 고정**한다.

| 항목 | 정한 내용 |
|---|---|
| 꺼내는 순서 | 입고 칸 1 → 2 → 3 (통로 쪽부터). 빈 칸을 지나 다음 칸으로 간다 |
| 넣는 순서 | 출고 칸 1 → 2 → 3 (동쪽 통로에서 먼 칸부터). 차를 실은 채 빈 칸만 지나간다. A/B 배치에서는 서쪽 통로에서 3 → 2 → 1이었다 |
| 받침대 | 바퀴 자리 대신 차체 앞뒤 끝 4곳 (차 기준 x ±2.05, y ±0.68 m). 행거 레일(±1.80 m)이 옆으로 들어갈 통로가 차 밑에 생긴다. 출고 칸도 같은 높이라 완성차를 받침대에 내려놓는다 |
| 높이 (행거 오프셋, 0 = 도킹) | 진입 -0.16 → 들어 올림·이송 -0.04 → 도킹 0. 칸의 차는 -0.09. 진입 때 행거의 팝업 위치결정 블록을 60 mm 내리고, 차를 들어 올린 뒤 올린다 (2026-11-26 라이브 물리 검증으로 -0.12에서 변경: 블록이 사이드실에 걸림, 패드가 휠 아치 끝에 닿음) |
| 회전 | 입고는 서쪽 통로 끝 (-7.5, 9.69), 출고는 동쪽 통로 끝 (13.1, -9.69)에서 제자리 90° (차가 쓰는 원 반경 2.53 m). 동쪽 회전 원에서 끝벽 기둥까지 약 0.7 m |
| 주행 | 고정 레인 추종. Nav2 자유 경로(MPPI)는 시험에서 레인을 벗어나 차를 돌렸다 |

A/B 배치에서 설계한 버퍼 왕복 경로: 통로 (-7.5, 9.69, -90°) → 입고 칸 차 밑 → 들어 올림 → 통로 → 0°로 회전 → 게이트 → 도킹 → 게이트 → 출고 통로 (-7.5, -9.69) → +90°로 회전 → 출고 칸 → 내려놓음. 값은 `wheel_cell/process.py`의 `BUFFER_*`, `AMR_LIFT_*`.

A/B/C 배치의 왕복 경로: 통로 (-7.5, 9.69, -90°) → 입고 칸 차 밑 → 들어 올림 → 통로 → 0°로 회전 → 게이트 → A·B·C → 출차점 (7.2, 0) → 동쪽 복귀 통로 (13.1, 0) → 출고 통로 머리 (13.1, -9.69) → +90°로 회전 → 출고 칸 → 내려놓음. 복귀 통로 값은 `wheel_cell/layout.py`의 `return_x`, 시간은 `process.py`의 `AMR_TO_RETURN`, `AMR_OUT_BUFFER`.

> ❓ **결정 필요:** 키프레임 시연은 아직 주문 차량이 통로 끝에서 이미 실린 채 나타난다. 칸에서 꺼내는 장면과, 칸이 3개인데 주문이 4대인 것(4번째 차를 둘 곳)을 정해야 한다.

위 버퍼 픽업 설계와 실험은 보존한다. 새 공정의 출고 경로는 전방 출차점 → 동쪽 복귀 통로 → 출고 칸 줄 머리이며, 출고 칸 동쪽 끝 가드는 통로 쪽으로 열었다. [버퍼와 공정 시험 기록](PROGRESS.md)
